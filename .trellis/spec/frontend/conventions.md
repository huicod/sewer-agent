# Frontend conventions

- Current package: frontend/, React + TypeScript + Vite. Keep UI state local until a concrete shared-state need appears; no generic chat framework.
- Use Ant Design with the shared Chinese locale/theme for independent conversations. The left navigation lists server-backed sessions, the main pane shows messages, and the optional right pane groups task history by exact asset ID/version and shows evidence. Navigation, context and composer options can collapse. Desktop detail width supports pointer/keyboard adjustment, persists locally and clamps to available width; mobile details overlay the conversation and hide the separator.
- Restore conversation context from the latest valid linked turn, then the first task if there are no linked turns. Typing a draft or explicitly choosing a task/reference/frame pins its target while browsing; show the exact target and allow an explicit return to the displayed task. Newly uploaded inspections and newly linked tool children follow their result; ordinary replies about another task must not reset detail navigation. Session-keyed in-memory drafts preserve File references, mode, target and pending retry identity across switches. Late acknowledgements may clear only the matching request, never a newer pending request or another conversation draft.
- Detector-only follow-up geometry requires an explicit new YOLO+VLM baseline, using the same original asset with a fresh retry-stable request ID. Pin the source before admitting the new task, switch context only after start succeeds, preserve the draft, and gate sending while that baseline is active. Never mutate an existing task mode or automatically send the geometry draft. Retry a lost admission with the identical payload and a lost start using only the admitted task ID.
- Manual intake opens in a modal. Closing it preserves the File, instruction and retry identity; successful submission clears the form. Use explicit text-area labels that remain stable after a modal reopens with a draft. At narrow widths, closed navigation must be hidden from keyboard and accessibility navigation, with Escape and focus return supported.
- Backend-owned contracts are projected in src/types.ts; src/api.ts owns the network boundary. Components do not embed server URLs/credentials or create runtime conclusions.
- Use same-origin /api via the local Vite proxy. Development binds 127.0.0.1; no production authentication or public deployment is implied.
- Session ID may be saved in browser localStorage; authoritative task/evidence data stays on the server. Reload restores a session, not a new inspection.
- Submission retries reuse request_id and the uploaded asset only for the same selected File and instruction/session. File names, sizes and timestamps are not content identity; no file hashing.
- Inspection mode is also part of task/turn retry identity; changing mode creates a new request while the identical File upload may be reused. Display the saved mode, not the current selector. Only completed, covered, actually processed empty detector-only runs can say 未检出五类缺陷; failures must not. Preserve detector_only_rules provenance and skipped_by_mode evidence; historical payloads may omit mode fields, invalid supplied values are not historical defaults.
- Video tool selection binds the parent task and exact persisted FRAME separately from uploads. Pending identity includes frame presence and AssetRef; only a non-null identical File can reuse an upload. Clear stale frame/pending state on target changes and disable selection/cancel during submission. Frame-child displays/reports are single-frame results, not whole-video conclusions; large evidence pickers start collapsed.
- Display real server stages/progress/errors; T04 queued means accepted but not executed. A chat-style page must not invent an assistant response.
- UI tests: npm --prefix frontend test; build/typecheck: npm --prefix frontend run build. This server needs .tools/node/bin on PATH, not its older system Node.
- Component tests use explicit HTTP-boundary responses; real backend/database integration is verified separately. Passing a DOM test is not visual browser acceptance.
- `npm --prefix frontend run test:e2e` typechecks the browser scripts and runs synthetic core and lost-acknowledgement acceptance by default. Lost-response tests forward the POST to real admission before aborting its response, then verify retry identity and persisted task counts. Real model/API browser scenarios require both `SEWER_RUN_BROWSER_LIVE=1` and `SEWER_RUN_LIVE_API=1` plus the documented image; preserve failed evidence and use a scenario filter instead of automatically repeating paid runs. Never submit fabricated human decisions for real CCTV.
- Enhancement evidence is an on-demand task panel; invalidate requests on task switch/close, refresh expanded panels with server revisions, and distinguish absent output from API failure. Draw ROI in original pixels and label enhanced images as auxiliary evidence, not restored truth or accuracy gains.
- Geometry follows the same on-demand/source/stale-response rules. Display actual mask/overlay and relative-depth assets, original-pixel prompts, finding IDs for dialogue, and explicit full-image denominator/relative units; never reinterpret mask score as defect confidence or render physical dimensions without calibration. Keep it read-only until a separate editor task is approved.
- Stored image provenance is an image/frame-only on-demand panel: keep original detector scores attached to original labels, show VLM advice and saved fusion actions as separate indexed history, and render current non-rejected findings without inventing revised-label confidence or recomputing missing evidence.
- Comparison selection binds `reference_task_id` into the same immutable pending-turn retry identity; clear it on session/input changes. Read comparison evidence per completed turn on expansion, invalidate stale requests, and separate absent results from errors. Show both frozen sources, coverage and review-status counts; count deltas never establish real temporal changes.

- Unified reports use `/api/sessions/{id}/report?format=json|html` and include every saved turn plus per-asset task/tool evidence. These are current server snapshots, with active work marked non-final; never sum repeated or inherited findings into a new defect total.

- Conversation organization uses server summaries and PATCH metadata. Per-row menus rename, pin/unpin and archive/restore; archive filters the sidebar only, preserving the active keyed controller and draft. Poll-derived summaries must preserve saved custom_title/pinned/archived. Apply mutation results after acknowledgement, retain rename input on failure, and start new conversations in the unarchived unfiltered view.
