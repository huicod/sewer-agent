# T15-D design

Reuse `VideoInspectionWorkflow`, `VideoActivities`, `video_run_config`, `HumanReviewRepository`, `MediaStore`, and test-only `LiveExecutionRecorder` / GPU measurement wrappers from `backend/tests/browser_live.py`. No production module changes are planned.

An opt-in integration test consumes explicit source/output environment variables, creates its own schema and Temporal queues, and starts the production workflow. Preserve the production human-review version and default semantic review budget (32); the measurement client imposes a separate physical API cap of 8 including retries. Observe the saved final checkpoint and the actual workflow human-review stage, or a terminal workflow; never wait indefinitely for a person. On cleanup terminate only the exact owned test workflow and drop only its generated test schema. Save evidence before cleanup and explain that these test tasks are not in the live app.

Measure activity durations using a test-only wrapper/subclass with Temporal activity names preserved; reuse the existing safe API recorder and measured detector. Include frame/batch counts, processed frames/chunks, source duration and dimensions, decode completeness, event intervals, evidence and selected review frames, tool calls, run pins, final task, per-activity durations, and GPU peak allocated/reserved bytes. Sum provider-supplied tokens only when present; unknown usage stays explicit. Save original evidence and overlay detector/final boxes using existing image utilities if feasible; raw frame and JSON linkage is required even without a new gallery.

Require `SEWER_RUN_VIDEO_COST_LIVE=1` and `SEWER_RUN_LIVE_API=1`; `SEWER_LIVE_VIDEO` must be an absolute existing file; `SEWER_VIDEO_COST_OUTPUT` must be a new path strictly under repo `var/evaluations`. Refuse oversized admission (>60 seconds) before GPU/API inference. Also require an explicitly configured `api_max_output_tokens` (Settings validates 1–8192), rejecting unset limits without changing production defaults; the documented and actual runs use 4096. No new CLI framework, dependency, resume scheduler, or billing subsystem. In-process polling is test observation only, not production orchestration. Pytest observation has a deadline; on failure persist available metrics before owned cleanup.

Historical full-video results remain separate: 561 and 3,698 frames from T08 establish earlier coverage but lack token measurements. New short-run normalized rates are observations/extrapolations, not a promise that arbitrary one-hour videos cost the same.
