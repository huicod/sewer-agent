# YOLO-guided balanced VLM review and per-image experimental evidence

## Goal

在固定 sewer2403 图片上检验 YOLO 引导的 VLM 复核能否同时改善精确率和召回率，并提供全部逐图证据供用户检查。

## Requirements

- 原始 YOLO 预测始终保存在记录中；实验融合允许明确证据的删除、改类，不把所有新增候选当成正确预测。不确定或调用失败时保留原候选并明确标记。
- 单次输入原图、最多 8 个带上下文的 YOLO 局部图、类别定义、框和分数。新增框用整图归一化坐标后端转换；GT 不进入模型或融合。
- 固定已有 36 张主集及 12 张回归集，缓存检测结果，一轮最多 48 次 API 调用；不换样本、重试失败或调低 IoU 追分。两组均非未见测试集。
- 使用同一批响应另做“仅逐框复核、不采纳新增”的离线消融，不增加 API 调用，帮助区分候选复核和补漏各自造成的误差；完整融合仍为本轮主结果。
- 记录 predictions（实际评分框）及 changes（保留/删除/改类/新增/待审原因），与 observation、review、review_error 并存。
- 全部图片提供原图、YOLO 框、融合框、GT 框和具体改动；图像内容不经生成式修改。
- 不改生产默认、不训练、不推进视频；未同时提高 P/R 不宣称成功或推广。

## Acceptance Criteria

- [x] TDD 实现引导复核、保守融合及全量逐图导出。
- [x] 固定两组实测，保存响应、错误、耗时及 class-aware IoU>=0.5 的 TP/FP/FN/P/R/F1。
- [x] 全部 48 张有原图和各阶段叠框，明确待审及零检测漏报补回。
- [x] 保存进度、审查差异并验证测试，不推送远端。

## Notes

- 主 agent 负责复核/融合/实测；独立子任务只负责静态图库及其测试，不共享写入文件。
- 顺序：TDD → 固定实测 → 全量图库 → 有界审查/验证/保存。复用客户端和契约，无新框架或依赖。
