# T05 design — durable image inspection

Approved roadmap scope, continuing T04 at 0c6d664b. Temporal is the only orchestrator; no new framework/model/dependency. T05 executes image inspection, not multi-turn planning (T06), video (T07), or a human-review UI (T09).

## Execution and boundaries

- Explicit POST /api/tasks/{task_id}/start starts an admitted IMAGE; duplicate starts use fixed workflow ID inspection:<task UUID> with reject-duplicate policy. Unsupported video returns 409 and stays queued. The UI adds an image-start action and shows actual results/failures. No automatic hidden backlog drain.
- Before start, persist a run record with immutable config and generated run_id UUID. A failed/ambiguous start can safely retry the same workflow ID/config. No second scheduler/outbox poller; explicit retry reconciles acceptance. Terminal reprocessing requires a new task.
- Config pins detector ID/model version/label-space, VLM model/base URL (no key), policy/prompt version, API timeout and max image bytes. Activities verify configured versions before using models; mismatches fail rather than silently changing a recovered run. Model files must not be overwritten under the same version.
- Workflow sequence: publish detecting -> serial GPU Activity (original detection + cheap quality metrics) -> publish verifying -> optional VLM Activity -> deterministic decision Activity -> persist final result. I/O never runs in Workflow. Activity results use JSON dictionaries and are checkpointed by (task_id, step); successful repeats return stored outputs. GPU concurrency 1; API worker separate. Transient API attempts capped at 3 with Temporal retries; schema/auth/missing config errors are not retried.
- Each detect/verify logical call has a stable call UUID/business key; each attempt has its own ToolCall record and status. External timeout/network failures are uncertain, not zero-cost guarantees; a later successful retry does not delete attempt history. Checkpoints and successful call records commit atomically. Progress writes update the existing TaskRecord projection, not another state machine.
- Final unresolved/conflicting/OTHER candidates produce partial/inconclusive (or partial/defects_found if other findings confirmed), with reasons for review. T09 implements the durable human-wait/resolution entry; T05 does not fake a waiting workflow without a reviewer.
- Failure after detection retains its evidence and candidate findings. Missing VLM configuration is visible and cannot result in normal. Whole image coverage plus adequate quality and an assessable completed full-image audit is required for normal.

## Binding interfaces for parallel work

Root owns workflow/**, API routes/app, config and worker/start scripts, UI edits and shared documentation. Storage agent owns storage/inspection.py + storage integration tests only. Vision agent owns contracts/inspection.py, vision/quality.py, agent/image_review.py, agent/image_policy.py + focused tests only. No overlapping writes or VCS operations by agents.

Vision contracts (inherit ContractModel):
- QualitySummary: mean_luminance(float), contrast(float), sharpness(float), adequate(bool), reasons(tuple[str,...]). Heuristic thresholds are versioned provisional engineering gates, not defect probabilities/calibrated accuracy.
- ImageObservation: detection: DetectionBatch; quality: QualitySummary.
- CandidateReview: index(int >=0 into DetectionBatch.detections), verdict(accept/revise/reject/abstain/need_more_context), proposed_label(DetectionLabel|None), reason(nonempty str max1000).
- AdditionalAnomaly: label(DetectionLabel|OTHER), name(str|None), bbox_xyxy(tuple of four finite floats|None), reason(nonempty str max1000). Dimensions checked against image at review boundary.
- ImageReview: image_assessable(bool), full_image_audited(bool), candidates(tuple[CandidateReview,...]), additional_anomalies(tuple[AdditionalAnomaly,...]), summary(nonempty str max2000).
- InspectionDecision: findings(tuple[Finding,...]), inspection_result(InspectionResult), coverage(CoverageSummary), needs_review(bool), reasons(tuple[str,...]).
- analyze_quality(path:Path) -> QualitySummary. Use Pillow/numpy or existing cv2; no enhancement or training.
- review_required(observation:ImageObservation) -> bool. True for zero detections, any score<0.85, FS/BX weak-class candidates, or inadequate quality. High-confidence other classes with adequate quality may skip VLM.
- decide_image(task_id:UUID, asset:AssetRef, observation:ImageObservation, review:ImageReview|None, review_error:str|None=None) -> InspectionDecision. No I/O; UUID4 Finding IDs are generated inside the final Activity and then persisted/cached.
- ImageReviewer(client:OpenAICompatibleClient,max_image_bytes:int=8388608); async review(path:Path, observation:ImageObservation) -> ImageReview. Send original full image and indexed detection metadata with JSON-only schema and domain labels. No arbitrary text execution. Validate exactly one review per detection (no duplicate/missing/out-of-range indices), bounds for additional boxes. Prompt version image-review-v1. No internal retry. Unsupported/oversize image -> safe nonretryable APIClientError. Missing config handled by root Activity.

Decision rules: without required review or on review failure, candidates stay unresolved; never normal. Agreement accept with original label can confirm by rules only when quality adequate and image assessable. Reject/revise of strong evidence (score>=0.85), abstention or missing context goes to review; weak rejected evidence may be rejected. Additional anomalies (including five-class suggestions) are review-only, OTHER never auto-confirmed. Any inadequate quality or incomplete required audit blocks normal; rejected-all requires full-image audited and no unresolved candidates. Coverage sufficient_coverage=True only for completed full-image primary detection; sufficient_quality follows quality + review assessability when reviewed. No VLM self-confidence substitutes for evidence.

Storage interface: InspectionRepository(PostgresRepository), initialize() calls super plus creates prefixed run/call/checkpoint tables; get_run(task_id)->dict|None; ensure_run(task_id,config:dict)->dict {run_id,task_id,config} first-write immutable; load_step(task_id,step)->dict|None; save_step(task_id,step,payload:dict,call:ToolCall|None=None)->dict (first write immutable, replay returns cached); record_call(call:ToolCall)->None upsert same call_id+attempt while preserving other attempts; list_calls(task_id)->tuple[ToolCall,...]; update_snapshot(snapshot:TaskSnapshot)->TaskRecord (lock/validate ID, preserve submission and no terminal-to-running regression). Methods use parameterized SQL, existing safe errors, bounded connections and unique test-owned schemas. No arbitrary model/UUID code supplied by clients.

Review ruling: detector transport failures may retry at most 3 times, reusing a committed checkpoint; deterministic model/config/OOM failures remain nonretryable. Final local DB persistence retries durably with capped backoff and cannot repeat API/model calls; configuration drift produces an explicit failed/inconclusive result with raw candidates retained. The final checkpoint and task projection use two recoverably convergent writes, not one atomic transaction.

## Validation

Pure rules/quality/VLM wire tests cover five labels, zero-normal audit, weak rejection, strong conflict, OTHER, poor quality and invalid JSON/indexes. Real PG tests cover config pins, successful checkpoint reuse/attempt history, recoverably convergent final checkpoint/projection and immutable submitted text. Temporal tests use real local server + dedicated queues and test-only detector/API adapters; worker stop/restart without restarting shared services proves cached detection not repeated and progress retained. Real GPU smoke uses only the previously authorized checkpoint and explicit local fixture. Real VLM remains pending user configuration and must be labelled separately.
