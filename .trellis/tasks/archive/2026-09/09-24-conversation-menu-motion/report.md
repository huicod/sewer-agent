# Result

- Root cause: the global reduced-motion selector assigned a nonzero transition duration to every element. With the CSS initial `transition-property: all`, Ant Design popup alignment's synchronous left/top writes became transitions; measured coordinates were stale and oscillated between negative and positive offscreen positions. Default-motion checks had missed this because Playwright `toBeVisible` accepts offscreen elements.
- Minimal fix: set reduced-motion transition duration to zero. Keep the short keyframe animation duration so Dropdown animation-end cleanup still runs. No component, API, schema, dependency or stored-conversation changes.
- Browser A/B on the served app: before the override, all 30 sampled frames were offscreen; setting only transition duration to zero kept all 30 in view. Evidence: `var/evaluations/conversation-click-debug/reduced-motion-reproduction.json` and screenshots.
- Regression red: the new real-browser test failed with viewport ratio 0. Green: both targeted browser tests passed, covering reduced-motion desktop/mobile menu viewport bounds, stable position, unchanged trigger/page scroll, usable rename modal, and normal rename/pin/archive/restore persistence. Evidence: `var/evaluations/conversation-menu-motion/{red,green}`. Tests use isolated synthetic storage; production interaction checks only open and cancel UI.
- Independent read-only review by `assistant_resize` confirmed the CSS/rc-trigger measurement cause and the one-value fix. Root reviewed the diff.
- Rollback anchor: parent jj change `zqxoqylw`, commit `13b29546`; fix change `unnnlzsz`. The unrelated experiment-results document is preserved in the parent.
